## PK/FK/UNIQUE/CHECK responsibilities

- UUID PK for each table; application UUIDv7 generation remains ADR-002.
- Inbox authorized_sender_id is NOT NULL and references authorized_senders.id. UNIQUE (source, source_instance, source_message_id). attempt_count >= 0. processing_status only received|processing|needs_confirmation|processed|failed|ignored.
- Interpretation inbox_message_id→inbox_messages.id. UNIQUE (inbox_message_id, attempt_number); attempt_number >= 1; confidence null or in [0,1]. Preserve VARCHAR intent/parser_type/status without inventing exhaustive enum/status CHECKs not supplied by physical design.
- Confirmation authorized_sender_id→authorized_senders.id; origin inbox_message_id→inbox_messages.id; nullable resolved_by_inbox_message_id→inbox_messages.id. No uniqueness on the origin/resolution references beyond documented requirements.
- Confirmation status only pending|confirmed|cancelled|expired. Pending requires resolved_at null; all terminal statuses require resolved_at non-null. target_version null or >= 1.
- Partial UNIQUE (channel, sender_reference) WHERE status = pending. No superseded status: cancellation reason can carry superseded_by_new_command.
- FKs preserve historical references with restrictive deletion; no cascade purging. Sender FK existence does not prove active sender authorization.

## Index responsibilities

Inbox indexes from database §44: (processing_status, last_attempt_at) for later retries/reclaim; (authorized_sender_id, received_at DESC) and (sender_reference, received_at DESC) for sender history; (correlation_id) for tracing. Composite Inbox uniqueness supports duplicate lookup.

Interpretation attempt uniqueness supports attempts per Inbox. Confirmation partial unique index supports finding/enforcing the one pending session for a channel/sender. No invented expiry queue, JSONB search or parser indexes.
