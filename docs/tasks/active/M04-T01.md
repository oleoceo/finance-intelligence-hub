## Allowed implementation surface

### packages/core

- `src/domain/finance/money.ts`: Money value object with `amount: string` (decimal) + `currency: string`; factory validates `amount > 0`, decimal format and currency pattern; no floating-point canonical representation.
- `src/domain/finance/transaction-types.ts`: `TransactionType = 'expense' | 'income' | 'transfer'`; `TransactionStatus = 'posted' | 'voided'`; `TransactionSource = 'direct_api' | ...` (extensible for M05+).
- `src/domain/finance/transaction-validation.ts`: pure validators for type/status/amount/currency/date invariants; future-date check accepts Book timezone as input (no clock import); inactive-entity rejection helpers.
- `src/domain/finance/human-ref.ts`: human_ref generation strategy consistent with frozen VARCHAR(16) UNIQUE; collision-safe within the same transaction boundary; deterministic test mode supported.
- `src/domain/finance/errors.ts`: financial error classes/codes including `BOOK_NOT_FOUND`, `BOOK_INACTIVE`, `ACCOUNT_NOT_FOUND`, `ACCOUNT_INACTIVE`, `CATEGORY_NOT_FOUND`, `CATEGORY_INACTIVE`, `MERCHANT_NOT_FOUND`, `MERCHANT_INACTIVE`, `TRANSACTION_DATE_IN_FUTURE`, `CURRENCY_MISMATCH`, `TRANSFER_SAME_ACCOUNT`, `CROSS_BOOK_TRANSFER_NOT_SUPPORTED`, `INVALID_TRANSACTION_TYPE`, `INVALID_TRANSACTION_STATUS`, `INVALID_AMOUNT`, `REFUND_BYPASS_REJECTED`. Reuse existing `MasterDataError` hierarchy where appropriate; do not duplicate codes already mapped in API error handler.
- `src/application/ports/transaction-ports.ts`: `TransactionRepository`, `TransactionReadPort`, `TransactionRecord`, `CreateTransactionInput`, `ListTransactionsInput`, `ListTransactionsResult`, `GetLastTransactionInput`. Ports must not expose Kysely/pg types.
- `src/application/ports/idempotency-ports.ts`: `IdempotencyKeyRepository`, `IdempotencyKeyRecord`, `CreateIdempotencyKeyInput`, `CompleteIdempotencyKeyInput`, `IdempotencyFingerprint` contract.
- `src/application/ports/audit-ports.ts`: `AuditWriter`, `WriteAuditEventInput` covering `TRANSACTION_CREATED` only in M04.
- `src/application/ports/financial-transaction-port.ts`: extend or compose `TransactionPort` to support financial-write context (Transaction repository + Audit writer + Idempotency repository + Locks + Master Data readers) without breaking existing M03 configuration transactions. Prefer composition over modifying the accepted `MasterDataTransactionContextT04` shape unless necessary for atomicity.
- Export all new public symbols from `packages/core/src/index.ts`.

## Implementation contract

- Money value object is immutable; equality by value; serializes to decimal string.
- Transaction validation is pure where possible; Book timezone is an explicit parameter, never imported globally.
- Financial errors carry stable machine-readable codes matching `05-API-CONTRACTS.md` §10.
- Ports are minimal and cohesive; no god-context.
- Human-ref strategy does not require external coordination beyond the DB transaction boundary.
- All new Core exports are covered by unit tests in this task.

## Concurrency and locking requirements

T01 does not implement locking but MUST define the financial transaction context shape so that T02+ can participate in the accepted M03 lock protocol. The financial write context must include access to `ConfigurationLockPort`, `BookRepository`, `AccountRepository`, `CategoryRepository`, `MerchantRepository`, `FinancialUsageReader` and the new `TransactionRepository`/`AuditWriter`/`IdempotencyKeyRepository` within the same PostgreSQL transaction.

## Required unit tests

- Money: valid/invalid amounts, decimal precision, currency format, immutability, serialization.
- Transaction types/status/source enums and guards.
- Validation: each invariant (type, status, amount, currency match, date not future given timezone, inactive entity rejection, refund bypass rejection for generic income).
- Human-ref: format, length, uniqueness simulation, deterministic test mode.
- Error codes: stable codes, inheritance, message safety.
- Port contracts: type-level compile checks; no Kysely/pg leakage.

None in T01. Integration begins in T02/T06.
