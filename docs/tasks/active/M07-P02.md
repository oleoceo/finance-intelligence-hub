## Goal and bounded implementation

Implement `POST /api/v1/transactions/{id}/void` with required Idempotency-Key
and body `{ version, reason }`. Require current positive integer version and
nonblank reason; strict schema. Apply posted → voided, set voided_at/void_reason,
increment version once and preserve the row/identity/creator provenance.

Add a separate `transactions:void` scope; canonical fingerprint includes target
ID, expected version and reason. Reuse PostgreSQL claim/locked lookup/complete and
canonical JSON/hash policy; preserve transactions:create behavior. Same key and
request returns stored logical result without another audit or increment, even
though the target is now voided. Same scoped key with changed target/version/reason
returns IDEMPOTENCY_CONFLICT. New key against an already-voided target does not
pretend to perform another Void (TRANSACTION_ALREADY_VOIDED); stale pending mutation
returns VERSION_CONFLICT. Complete replay lookup before current-state rejection.

Under review §5 locks, reject original Expense with any posted Refund as
409 TRANSACTION_HAS_POSTED_REFUNDS. Allow Refund Void, locking its original before
the Refund. Ignore voided Refunds for the original guard. Audit
TRANSACTION_VOIDED with old/new snapshots and trusted actor/source. Mutation,
audit and idempotency completion commit or roll back together. Expose caller-owned
execution for P05; no independent commit in an Inbox transaction.

## Acceptance criteria and required tests

- Unit: state/version/reason validation, immutable identity, posted-refund block, exact fingerprint separation and replay/conflict decisions.
- PostgreSQL: expense/income/transfer Void; Refund Void; posted Refund blocks original; all Refunds voided permits original; one audit and one version increment.
- Same-key concurrent duplicate requests yield one effect and persisted replay; target/version/reason changes conflict; different keys cannot Void twice; stale version has zero effects.
- Inject audit/idempotency failure and prove rollback of status/version/void metadata; retry succeeds once. Stored replay survives later reads and is not recomputed from mutable state.
- API: required/malformed key, schema, admin-only auth, exact success envelope and frozen domain error codes; deterministic independent-backend Void/PATCH race.
