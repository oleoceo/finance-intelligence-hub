## Goal and bounded implementation

Implement `PATCH /api/v1/transactions/{id}` across API, Core and PostgreSQL.
Body requires integer version >= 1 and a bounded ordinary patch. Reuse Money,
reference validators, TransactionRecord, financial context and serializer.
Extend the existing repository with locked target read, posted Refund aggregate/
earliest-date read and conditional update; exact TS names may follow repository
conventions, but these semantics are mandatory.

Allow only amount, account_id, category_id, merchant_id, description, notes,
transaction_date. Explicit null clears only nullable fields; omission preserves
existing value. Reject unknown/server fields including destination_account_id,
currency, source_reference, inbox_message_id, id, human_ref, book_id, type, status,
source, refund_of_transaction_id, created_at and timestamps. Reject a body with no mutable field; same-value fields still follow the ordinary
versioned mutation contract.

Load target, preserve effective unchanged fields, acquire configuration locks and
target/original locks under review §5, re-read, validate and update using expected
version. Return 404 TRANSACTION_NOT_FOUND for absent target and
409 VERSION_CONFLICT for stale expected version; refuse mutation of a voided target.
Refund target returns REFUND_IMMUTABLE. Compare exact effective amount against sum
of posted Refunds and effective date against earliest posted Refund date, even
before P03 can create Refunds through the API.

Successful Correction increments version once, updates updated_at and emits
TRANSACTION_UPDATED with complete old/new snapshots in the same transaction.
Extend AuditAction and oldData typing; reuse KyselyAuditWriter. API returns the
updated serialized Transaction under the existing data/meta envelope. Preserve
trusted provenance and error mapping. PATCH does not require Idempotency-Key.
Provide caller-owned execution for later Inbox integration without nested commits.
