## Goal and bounded implementation

Consolidate proof that Correction, Void and Refund use the same original-Expense
serialization and existing configuration ordering. Inspect P01–P03 code, then
correct only demonstrated defects within those surfaces. Do not redesign ports
or replace locks with Redis, process mutexes or elevated isolation.

For each race coordinate two independent PostgreSQL backends and deterministic
barriers, observe actual waiting/lock ownership and assert final persisted
financial state, versions, audit and idempotency. Test both meaningful orderings.
The permitted outcome is an equivalent serial execution: no over-refund, no
original voided with posted Refund, no corrected amount/date violating Refunds,
and no duplicate effect. Version conflict is a valid rejection only when stale;
do not mask arbitrary failures as success.
