## Recommendation

**Recommended Approach: Reuse Existing Docker Engine Inside Ubuntu WSL2**

### Rationale

1. **Already Operational:** Docker Engine v29.8.0 is already installed, active, and healthy inside the existing Ubuntu 26.04 WSL2 distribution. No installation is required.

2. **Proven Track Record:** Evidence (existing images like `node:24`, `postgres:18`, `playwright`; named volume `anticlone-local_postgres-data`) confirms this runtime was successfully used by previous Codex projects on this exact machine.

3. **Testcontainers Compatibility:** Testcontainers for Node.js natively supports Docker Engine via Unix socket. When Node/Vitest runs inside WSL2, it connects directly to `/var/run/docker.sock` with zero configuration.

4. **Docker Desktop Incompatible:** Current Docker Desktop requires Windows 10 build ≥19045 (22H2). This machine runs build 19044 (LTSC 2021), making Docker Desktop unsupported and uninstallable without OS upgrade.

5. **Resource Efficiency:** Reusing the existing Docker Engine avoids the overhead of installing additional runtimes or creating duplicate WSL distributions.

6. **Isolation Safety:** Finance Hub will use project-specific naming (`finance-hub-*` containers, networks, volumes) to coexist safely with existing assets from other projects.

### Execution Model Decision: Model B (All Inside WSL2)

**Selected:** Node.js, Vitest, Testcontainers, and Docker all run inside Ubuntu WSL2.

**Analysis vs. Model A (Windows Node → WSL Docker):**
- **Model A Risks:** Requires exposing Docker socket over TCP or named pipe from WSL to Windows, introducing security complexity and potential Testcontainers connectivity issues. Cross-OS filesystem access (`/mnt/c/...`) causes severe performance degradation for `node_modules` and file watching.
- **Model B Benefits:** Native Linux socket access, native Linux filesystem performance, no cross-OS boundary for dependencies or test execution.
- **Repository Location & Filesystem Performance:**
  - The existing Windows-side repository at `C:\Projetos\finance-intelligence-hub` can be accessed from WSL2 via `/mnt/c/Projetos/finance-intelligence-hub`. This is functionally valid for Git operations and editing but suffers from lower I/O performance compared to the native WSL2 filesystem.
  - A true Linux-native clone or worktree (e.g., `~/src/finance-intelligence-hub`) would provide optimal performance for `pnpm install` and `vitest` but requires maintaining two copies or using Git worktrees.
  - **Decision:** Whether a separate Linux-native worktree is necessary will be decided empirically in M01-T04 based on actual performance measurements. No worktree will be created during M01-T03.
  - **Important:** Windows and Linux `node_modules` must never be shared or reused across runtimes due to binary incompatibility.
