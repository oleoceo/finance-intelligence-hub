**Status: code/CI preparation only.** Issue #100 does not activate Production, Gate C, real data, or a release. A human operator must receive separate authorization for each host operation. The Production database is a required future identity, not an assertion that it exists.

## Production backup activation gate (human operator, after Gate C authorization)

1. Preserve the existing M09-P06 Lab checkout, backup artifacts, Restic repository, credentials, services and timers. Inventory their unit status without changing them. Use a separate reviewed Production checkout at `/opt/apps/apps/production/finance-hub-v01`; inspect its exact SHA and CI result.
2. Confirm the `postgres-products` network is internal and the expected PostgreSQL instance is attached. Confirm `finance_hub_prod` exists only after separately approved bootstrap. Create a dedicated `finance_hub_prod` backup login with CONNECT/SELECT needed by `pg_dump` and no write, CREATE, superuser, replication, or BYPASSRLS rights. The runner verifies these rights before dumping. Never use an application/admin credential.
3. Provision `/opt/apps/backups/databases/finance-hub/production` and `/opt/apps/backups/restic/finance-hub-production-v01` as private `0700` directories owned by the human operator `leoceo`. Initialize the **new**, empty Production Restic repository with a distinct password. Place a random 32-hex ownership ID in `.finance-production-v01-owned` (mode `0600`) at its root. Use an independent rclone destination under `finance-drive:FinanceHub-Backups/finance-production-v01/<unique-id>`; never reuse a Lab prefix or repository. Place Production-only `PGPASSFILE`, `RESTIC_PASSWORD_FILE`, and `RCLONE_CONFIG_FILE` under `/etc/finance-hub/production/` as operator-owned `0600` files. Keep recovery copies of both secrets outside the VPS. No credential contents belong in Git, shell arguments or logs.
4. Create an external `/etc/finance-hub/backup-production-v01.env` with `FINANCE_PRODUCTION_SCHEDULE_ENABLED=yes`, `FINANCE_BACKUP_ALLOWED_DATABASE=finance_hub_prod`, `PGHOST=postgres-products`, `PGPORT=5432`, the dedicated `PGUSER`, `FINANCE_BACKUP_ROOT=/opt/apps/backups`, `FINANCE_RESTIC_REPOSITORY=/opt/apps/backups/restic/finance-hub-production-v01`, `FINANCE_RCLONE_REMOTE` in the dedicated prefix, and the three credential file paths. Pin `FINANCE_P06_CLIENT_IMAGE_ID` to the reviewed PostgreSQL 18 client image ID. Verify the env file is private and contains paths and identity only.
5. Inspect the seven `finance-hub-production-*` systemd units in this repository and their checkout path before installation. Run a separately approved manual `daily` backup, verify custom dump, manifest, encrypted remote slot and status; then run a weekly integrity check. Recover an off-site copy into an isolated target, compare manifest/hash and validate application reads before any real financial data. Never restore into Production as the first restore. Capture dated redacted evidence. Enable the Production daily, weekly and hourly status timers only after those checks and human approval. Check daily freshness and failure journal. Perform a new verified backup before any Production migration; retain 2–3 local managed dumps and Restic 14 daily/8 weekly/12 monthly snapshots.

The Production runner rejects other database names, Lab paths and Lab remote prefixes. Its lock, markers, registry, repository and service names are separate from P06 Lab. It checks ownership before retention and remote sync; an unknown object causes failure. No plaintext dump is uploaded. If any identity, permission or restore evidence is missing, stop activation and keep Production unavailable for real data.
