## Implementation contract

Authentication and scope evaluation run before Idempotency-Key and path/query/body validation and before Core/DB mutation. Missing/invalid credential yields 401 `UNAUTHORIZED` even with missing key/invalid body; valid ingest-only credential yields 403 `INSUFFICIENT_SCOPE` under the same circumstances. Rejected authentication causes zero Core/DB mutation.

POST `/api/v1/transactions` accepts only type expense/income/transfer and T01 Money strings/real calendar dates. Strict schema rejects unknown and server-controlled fields, `type=refund`, and client `refund_of_transaction_id` even when null. Transfer input also rejects category_id/merchant_id including null. Required Idempotency-Key is nonblank UTF-8 and <=255 characters; missing/invalid key gives 422 `VALIDATION_ERROR`. API passes validated command, key and request context to Core GenericCreateTransaction only. It must not expose T02/T03/T04 executors directly. New create succeeds with 201; successful replay returns the same logical `data` and 201, with fresh HTTP request_id/correlation_id.

GET List, Last and Get-by-ID succeed with 200. List book_id is optional: finance:admin can list across Books when omitted; supplied book_id filters exactly that Book. Optional type/status/account_id/category_id/merchant_id/date_from/date_to/search remain available. Search is case-insensitive over description, notes and source_reference. page defaults 1; page_size defaults 50 and maxes 100. Last alone requires book_id, filters posted and orders created_at DESC, id DESC. Get-by-ID has no invented per-Book authorization.

| Condition | HTTP | Public code |
| --- | ---: | --- |
| Missing/invalid credential | 401 | UNAUTHORIZED |
| Valid credential without finance:admin | 403 | INSUFFICIENT_SCOPE |
| Malformed type/amount/date/key/path/query, unknown or server-controlled field (including refund field even null) | 422 | VALIDATION_ERROR |
| Missing Book/Account/Category/Merchant | 404 | BOOK_NOT_FOUND / ACCOUNT_NOT_FOUND / CATEGORY_NOT_FOUND / MERCHANT_NOT_FOUND |
| Inactive Book/Account/Category/Merchant | 422 | BOOK_INACTIVE / ACCOUNT_INACTIVE / CATEGORY_INACTIVE / MERCHANT_INACTIVE |
| Missing Transaction | 404 | TRANSACTION_NOT_FOUND |
| Future transaction_date, same-account Transfer, cross-Book Transfer, currency mismatch | 422 | TRANSACTION_DATE_IN_FUTURE / TRANSFER_SAME_ACCOUNT / CROSS_BOOK_TRANSFER_NOT_SUPPORTED / CURRENCY_MISMATCH |
| Same key with different fingerprint | 409 | IDEMPOTENCY_CONFLICT |
| Database unavailable or bounded lock/wait retry exhausted | 503 | DATABASE_UNAVAILABLE |
| Unexpected failure or human_ref attempt exhaustion | 500 | INTERNAL_ERROR |

Error and success envelopes retain frozen API sections 8 and 9 style. Never put credential values in response, Audit, logs, fingerprint or source_reference.
