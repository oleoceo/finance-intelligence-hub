## Canonical HTTP Contract

Unless a frozen document explicitly specifies otherwise, define the M01 contract exactly as:

**GET /health**
- HTTP 200
- Body: `{ "status": "ok" }`

**GET /ready (PostgreSQL readiness succeeds)**
- HTTP 200
- Body: `{ "status": "ready" }`

**GET /ready (PostgreSQL unavailable/unusable/check fails)**
- HTTP 503
- Body: `{ "status": "not_ready" }`

Do not expose raw PostgreSQL errors, hostnames, credentials, connection strings, stack traces, or internal dependency details in these HTTP responses.

---

## Bounded Readiness Behavior

Define the M01 readiness budget as:
- One PostgreSQL readiness attempt per HTTP request.
- No retries inside `/ready`.
- Maximum connection/query readiness budget: 2000 ms.
- Timeout/failure results in HTTP 503.
- Timeout/failure must not crash or poison the Fastify process.

A minimal read-only query such as `SELECT 1` is acceptable.
No schema/data mutation and no migration execution.

## PostgreSQL Dependency Ownership

Preserve the rule that the existing `packages/database/**` baseline must be inspected first.
- If M01-T06 implements the readiness connection directly in `apps/api`, the approved `pg` driver must be declared as a direct runtime dependency of `apps/api`; do not rely on a root devDependency or transitive dependency.
- If the readiness abstraction belongs in `packages/database`, `pg` must instead be a direct runtime dependency of that package.
- Do not add Kysely merely for M01-T06 if it is not already required/installed by the existing database baseline.
- Do not introduce another PostgreSQL driver or health-check package.
- Any database Pool/Client owned by the application must have an explicit lifecycle and be cleanly closed on Fastify/application shutdown so tests and process shutdown do not leak connections/resources.

## Failure Behavior

- Readiness failure must **not** crash the API process.
- The application should remain responsive to `/health` even when `/ready` fails.
- Log readiness failures with a safe diagnostic classification/message appropriate for operations, ensuring no secrets are exposed.
