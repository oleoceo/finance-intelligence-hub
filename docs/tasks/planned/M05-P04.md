## Acceptance

- Exactly `pending`, `confirmed`, `cancelled`, `expired`; default TTL 15 minutes from creation. One pending session per `(channel, sender_reference)` enforced by existing partial unique index and row locking; uniqueness conflict yields safe retry/serialized result.
- Store origin `inbox_message_id`, `resolved_by_inbox_message_id` for reply resolution, `action`, payload, expiry, and target ID/version where applicable. M05 does not execute M07 destructive actions. A contextual `sim`, `não`, `1`, `2` requires one active pending session; late/duplicate replies cannot execute twice.
- A new complete command supersedes pending session with `resolution_reason = superseded_by_new_command`; old payload cannot execute afterward. Expiration and cancellation finalize original `needs_confirmation` Inbox to appropriate terminal state. Confirmed financial create finalizes original Inbox only in P05's shared commit with the financial effect. Resolver Inbox also becomes terminal. No original Inbox remains indefinitely `needs_confirmation` after resolved/expired/superseded session.
- Lock session/origin/resolver rows in a documented deterministic order. Concurrent replies, supersede and expiry produce exactly one winning transition; no duplicate financial effect.

**Required tests:** Core state/TTL/short-reply unit tests; real PostgreSQL integration for one-pending index, creation, confirmation, cancellation, expiry, supersede, linked Inbox finalization and independent-connection races with deterministic barriers. Assert all linked rows and no old command effect. P05/P06 test confirmed financial commit.
