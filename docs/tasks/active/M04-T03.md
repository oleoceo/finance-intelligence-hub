## Implementation contract

- Ordinary Income requires: book_id, account_id, amount, description, transaction_date. Optional: category_id, merchant_id, notes, source_reference.
- Server controls: id, human_ref, status = posted, version = 1, timestamps, source, refund_of_transaction_id = null.
- Client-supplied refund_of_transaction_id (even if null explicitly) is accepted only when absent or null; any non-null value triggers REFUND_BYPASS_REJECTED before persistence.
- Same locking, re-read, and retry protocol as T02.
- Structural CHECK (destination_account_id IS NULL for income) verified at DB level.

## Concurrency and locking requirements

Identical to T02: Book → Account → (Category → Merchant) lock order; re-read after lock; bounded retry.
