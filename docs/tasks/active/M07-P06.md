## Goal and bounded implementation

Verify the complete M07 lifecycle through composed API/Core/real PostgreSQL and
synthetic Inbox entrypoints, reusing all accepted P01–P05 behavior. Endpoint wiring
for mutations is delivered incrementally. Implement the two remaining frozen
administrative reads here: `GET /api/v1/transactions/{id}/refunds` and
`GET /api/v1/transactions/{id}/audit`. Fix only proven acceptance defects in
earlier tasks. Produce concise evidence linking criteria to tests and the exact
CI head.

Both GETs require `finance:admin`, use a strict UUID `id` path schema and
reject unexpected query parameters. Resolve the target Transaction through Core
read ports. Return the established API `data`/`meta` envelope, with explicit
response schemas for a Refund Transaction collection and an append-only audit
event collection; expose no credentials or raw Inbox content. The Refund read
targets an Expense and returns its linked Income Transactions (including voided
Refunds so history remains visible), each with its current status and version.
The audit read returns events for the target Transaction in stable chronological
order, with action, source, actor reference, old/new snapshots, correlation ID and
timestamp. A Refund's own audit is queried by its own Transaction ID; it must not
be conflated with the original Expense's audit. Use the existing Transaction and
AuditEvent representations without inventing a report or balance calculation.
Missing/invalid targets use established 404/validation errors; neither GET
requires an Idempotency-Key or mutates financial, audit or idempotency state.

Mandatory frozen critical scenario, with version read from each current response:

```text
Expense 500
→ Refund 200
→ correction to 450: VALID (450 >= 200)
→ correction to 100: INVALID (100 < 200 posted refunds)
→ Void Expense: INVALID (has posted Refund)
→ Void Refund: VALID
→ Void Expense: VALID (Refund now voided)
```

Assert stored amount/status/version, retained identity/history, linked Income and
audit after every step. Failed correction/Void cannot mutate or create audit/key
completion. Refund Void frees the original only when no posted Refund remains.
Use decimal strings 500.00/200.00/450.00/100.00 in executable requests.
Do not substitute a summary/report assertion for financial persistence evidence.
