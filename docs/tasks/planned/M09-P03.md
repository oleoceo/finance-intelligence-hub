# M09-P03 — Scheduler, retention and monitoring

**Status:** PLANNED. **Phase:** local/CI. **Dependencies:** accepted P01–P02 and explicit task activation. **Authority:** `07-SECURITY.md`, `08-BACKUP-RESTORE.md`, `09-ROADMAP-TESTS.md`.

**Goal:** Version daily systemd service/timer templates, retention/check procedure and visible failure reporting.

**Allowed paths when activated:** `scripts/backup/**`, `infra/finance-backup/**` templates, `scripts/backup/tests/**`, M09 runbooks/task docs.

**Acceptance:** Parameterized daily timer and weekly Restic check; off-site `forget/prune` retains 14 daily, 8 weekly, 12 monthly; local staging retains 2–3 recent valid dumps. A lock prevents concurrent runs, including timer/manual overlap. Interrupted runs release locks safely without deleting unrelated data. Failure or last successful backup >24h is visible and cannot be reported as success; monitoring does not expose secrets. RPO/RTO remain targets pending operational measurement.

**Required tests:** Timer/unit static validation where available, retention over synthetic dated snapshots, lock contention, interruption/restart, failed dump/remote/check, stale-success alert, bounded cleanup, logging/redaction. Use real local Restic for snapshot policy.

**Excluded:** Installing/enabling timers, host monitoring configuration, n8n as sole scheduler, VPS changes, real retention deletion.
