## Exact scope and schema objects owned

Own audit_events, idempotency_keys, outbox_events with exact physical types/lengths/defaults/nullability from database §§83–94:

| Table | Architectural columns |
| --- | --- |
| audit_events | UUID id; required entity_type, entity_id UUID, action, source; nullable actor_reference, old_data JSONB, new_data JSONB, correlation_id UUID; required created_at |
| idempotency_keys | UUID id; required scope, idempotency_key, request_hash, status; nullable resource_type/resource_id UUID, response_status INTEGER, response_body JSONB; required created_at; nullable completed_at |
| outbox_events | UUID id; required event_type, aggregate_type, aggregate_id UUID, payload JSONB; status default pending; attempts INTEGER default 0; required available_at; nullable locked_at/locked_by/published_at/last_error; required created_at |

TIMESTAMPTZ for technical timestamps. Outbox uses the physical published_at field, not a new processed_at field; see overview interpretation. IDs remain application UUIDv7. No expires_at or expiry routine for idempotency; no extra outbox delivery/deduplication fields.

## PK/FK/UNIQUE/CHECK responsibilities

- UUID PK on each table.
- Audit entity_id is polymorphic and explicitly has no generic FK (database §84). No guessed action/source enum or audit update timestamp.
- Idempotency UNIQUE (scope, idempotency_key); only in_progress|completed. in_progress requires completed_at null; completed requires it non-null. Preserve documented nullable response/resource fields without adding unsupported completeness/hash-format CHECKs.
- resource_id and outbox aggregate_id are polymorphic; no guessed FK or UNIQUE constraint.
- Outbox statuses only pending|processing|published|failed. Preserve documented attempts/default metadata; do not invent lifecycle CHECKs, retry states or extra constraints.
- T05 owns grant enforcement for logical append-only Audit. No business/audit mutation triggers in T04.

## Index responsibilities

Audit indexes from database §85: (entity_type, entity_id, created_at DESC) for entity history; (correlation_id) for tracing; (action, created_at DESC) for action history. Idempotency unique scope/key index supports lookup and competing reservations. PKs support canonical identity. No speculative Outbox polling index or payload index is specified by the frozen physical design, so none is introduced here.
