## Core behavior

- CreateBook validates name, uppercase three-letter currency and IANA timezone (default America/Sao_Paulo); stores raw/normalized name, server ID/timestamps, active=true, archived_at=null.
- UpdateBook allows name/timezone and currency only before any Account or Transaction is associated. Inactive Accounts also block a currency change. Query actual persistence; M04 not starting does not prove no financial rows exist.
- CreateAccount locks/validates active Book and derives its currency; type is checking, savings, cash, credit_card or other. institution_name/notes are optional per schema.
- UpdateAccount allows name/institution_name/notes and type/currency subject to lifecycle. book_id is immutable after creation. Currency/type changes after any Transaction use are rejected in M03. Currency must always equal Book.currency, even before use; no FX or Book move.
- ArchiveBook/ArchiveAccount set inactive/server archived_at, preserving history. Any sender default reference blocks archive, including an inactive sender. Remove/change defaults first. Repeat archive preserves the timestamp.
- Accounts alone do not block Book archive: ledger §§82–90, requirements §65 and domain §19 impose no such prohibition. Historical Transactions do not block archive. Do not cascade to Accounts/Rules.
- Get/list retain inactive rows. T05 owns routes, filters, ordering and exact HTTP mapping.

## Core ports and Database adapters

Core owns BookRepository/AccountRepository and T01 read/transaction contracts. Database implements Kysely persistence, ordered locks and the transaction scope; all operations in one use case share its connection.

T02 implements, without waiting for T04:

1. FinancialUsageReader: EXISTS by transactions.book_id; Account usage by account_id OR destination_account_id. No status filter: posted and voided history count. No financial row writes or money calculations.
2. SenderDefaultReferenceReader: EXISTS by authorized_senders.default_book_id/default_account_id, without active filter. This is the single owner of those queries. T04 reuses/composes it; Book/Account/full Sender repositories do not duplicate it.

Tests may seed existing authorized_senders/transactions through schema fixtures. No Authorized Sender configuration behavior or T04 repository method is needed for T02 completion.

## Concurrency contract

Use the overview protocol: FOR UPDATE held to commit, Books before Accounts, UUID ordering, re-read current state after locks. Book archive/currency update locks Book before default/dependency/usage checks. Account creation locks Book before active/currency validation and insert. Account update/archive locks Book then Account before usage/default checks.

T04 sender assignment/removal must lock the same referenced rows. T02 race tests use a minimal fixture writer following this protocol, not Sender CRUD. Assignment-first causes archive DEFAULT_*_IN_USE; archive-first causes assignment *_INACTIVE; removal-first permits archive. Account creation-first permits later Book archive absent defaults; archive-first rejects creation. Book currency/CreateAccount must preserve currency equality in either order.

Future financial writers must take Book/Account locks before validation/write. M03 tests prove guard queries and PostgreSQL FK-insert interactions using synthetic fixtures, without implementing or claiming M04 behavior.
