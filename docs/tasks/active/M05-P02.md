# M05-P02 — Deterministic interpretation

**Status:** ACTIVE / NOT AUTHORIZED FOR IMPLEMENTATION. **Prerequisites:** accepted review and P01 accepted interfaces. **Closure:** Draft PR and exact-head CI GREEN → REVIEW REQUIRED; DONE only after human acceptance.

## Objective and ownership

Build a pure Core interpretation model that parses one authorized message into at most one typed, partial intent candidate or a typed unknown/ambiguous/confirmation outcome. P02 extracts explicit user values; P03 resolves omitted references, Book context and defaults. No AI provider is required.

**Permitted paths:** `packages/core/src/domain/inbox/**`, `packages/core/src/application/inbox/interpret-message.ts`, `packages/core/src/application/ports/interpretation-ports.ts`, `packages/core/src/index.ts`, corresponding Core `*.test.ts`. P02 may define Interpretation record/attempt interfaces; PostgreSQL persistence of attempts belongs to P05 composition using P01 transaction facilities.

**Dependencies/interfaces:** consume P01 normalized authorized message type and M04 Money validators through Core modules. Return a discriminated `create_transaction | query_last | reply | unknown/ambiguous` interpretation. A create candidate carries type and only parsed fields: decimal-string amount, description, optional Book/Account/destination Account/Category/Merchant references or names, and an optional date expression (`hoje`, `ontem`, `anteontem` or pt-BR date). Each supplied value retains explicit-input provenance; omitted fields stay absent. It is not `CreateTransactionInput`. A `query_last` candidate carries an optional explicit Book reference/name and no financial create payload. P03 owns resolution to the final M04 `CreateTransactionInput` at the create command boundary. P05 persists `interpretations` by `(inbox_message_id, attempt_number)`.

## Acceptance

- Deterministic grammar covers accepted V0.1 Expense, Income, Transfer and `query_last` (`último`, `último empresa`) examples; no external AI call. One message produces at most one intent. Multiple commands, unsupported intent, missing required data and ambiguous values never post silently; return typed clarification/confirmation or safe failure. `resumo` remains deferred to M08.
- Explicit amount, Book, Account, Category, Merchant, date and transaction type outrank inference. Validate exact decimal-string Money and positive amount when supplied. Preserve the raw date expression and whether it was explicit; do not assign a default date or evaluate relative dates before P03 resolves the Book timezone. P03 applies the received local date as the omitted default, resolves `hoje`/`ontem`/`anteontem` and pt-BR `DD/MM` or `DD/MM/YYYY`, and checks future dates against the current Book-local date before M04 create. Parser cannot introduce float money, `occurred_at`, FX, cross-Book or refund as a generic type.
- Contextual short replies (`sim`, `não`, `1`, `2`) are identified as reply candidates for P04, not standalone financial creates. Edited/deleted message content does not mutate earlier Transactions.

**Required tests:** unit matrix for deterministic variations, explicit provenance and absent fields, malformed/ambiguous/multiple commands, reply tokens, exact Money inputs, preserved `hoje`/`ontem`/`anteontem`, `03/09` and `03/09/2026` expressions, `último` and `último empresa` typed `query_last` candidates, and no AI configuration. Assert P02 does not emit a completed `CreateTransactionInput` or execute a read. No PostgreSQL test is required for this pure slice; P05/P06 own real PostgreSQL Interpretation persistence and full pipeline tests. Retain all M04 tests.
