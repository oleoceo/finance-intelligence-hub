## 5. Ownership, transport, security and reliability

Evolution owns webhook/send transport; n8n owns trusted webhook ingress, technical event filtering, exact envelope mapping, bounded retries and outbound delivery; Finance API owns service auth, sender auth, Inbox identity, parsing, resolution, confirmation, financial writes, idempotency and reply content. P01 must specify a source instance stable across restarts, provider message ID without regeneration, sender reference from verified sender metadata, event timestamp, supported incoming text events, and only `is_group`/`from_me` flags. Unknown payload keys are not forwarded. Any provider payload fixtures are illustrative pending version/payload verification after Gate 0; no invented live schema is normative.

**Evolution → n8n authenticity boundary:** Before normalization or any Finance call, the ingress must establish that an event originated from the configured trusted Evolution instance using a verification or access restriction supported by the real deployed version and validated by Gate 0 evidence. A hard-to-guess webhook URL alone is not authentication. Bind the verified origin to the configured instance identity; do not accept an instance name, sender number, message ID, or `from_me`/group flags merely because an untrusted payload supplies them. Validate sender metadata against the provider's verified incoming-message context and reject missing, malformed, conflicting, spoofed, or cross-instance identity. Reject unknown/untrusted origin, unsupported event, group, and `from_me` events before Finance forwarding. If the origin or sender binding cannot be established, fail closed with no Finance call, no outbound reply, and no financial effect. Finance's AuthorizedSender check remains a second boundary, not a substitute for ingress authenticity. The exact origin proof, deployment restriction, trusted metadata fields, and negative fixtures are conditional on the real Evolution/n8n versions and Gate 0; live promotion stops if this proof is unavailable.

Keep Evolution ingress verification material, Evolution send credentials, and the Finance `finance:ingest` credential separate, with scoped access and environment-specific provisioning. n8n must never hold `finance:admin`. Do not put credentials, real webhook payloads, real sender text, authorization material, or unredacted failures in repository fixtures, execution logs, or routine diagnostics; retain only bounded identity/correlation, verification outcome, status, and reply ID. P01 specifies this contract; P02 proves enforcement before forwarding.

Finance call retry: bounded backoff for 500/503/timeouts; 429 honors Retry-After within a maximum delay; 400/401/403/409/422 are not blindly retried. An ambiguous Finance response may be retried only with the *same* identity. Outbound send retry is a separate bounded queue/path and never calls Finance create again. A send timeout can have delivered the message; reply delivery is best effort, not exactly once. Log only identity/correlation/status/reply ID, not credentials or raw text. No finance:admin token in n8n, no raw unauthorized Inbox persistence, no financial parsing or SQL in workflow.
