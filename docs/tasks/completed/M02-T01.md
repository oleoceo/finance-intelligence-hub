## PK/FK/UNIQUE/CHECK responsibilities

- books: UUID PK; UNIQUE normalized_name and (id, currency); uppercase three-letter currency CHECK; active/archive consistency.
- accounts: UUID PK; book_id FK and composite (book_id, currency)→books(id, currency); UNIQUE (book_id, normalized_name), (id, book_id), (id, book_id, currency); uppercase currency CHECK; type only checking|savings|cash|credit_card|other; active/archive consistency.
- categories: UUID PK; book_id→books.id; UNIQUE (id, book_id); nullable (parent_category_id, book_id)→categories(id, book_id); prohibit direct self-parent; type only expense|income|both; active/archive consistency. Root normalized-name uniqueness per Book and child uniqueness per Book/parent use the documented partial unique indexes.
- merchants: UUID PK; active/archive consistency follows ledger §84/domain §20; normalized_name is not globally UNIQUE. Do not introduce tax-identifier uniqueness before normalization is specified.
- classification_rules: UUID PK; four nullable target FKs; at least one non-null target; match_type only exact|contains; source only manual|system. No undocumented positive-priority constraint or cross-target composite rule.
- authorized_senders: UUID PK; UNIQUE (channel, sender_reference); default_book_id→books.id; composite (default_account_id, default_book_id)→accounts(id, book_id); default Account requires default Book.
- Restrictive deletion preserves referenced rows. Active state is not part of a historical FK. Longer category cycles, compatible rule targets, active defaults and currency/type immutability are Core responsibilities.

## Index responsibilities

Use PK/UNIQUE-backed indexes for identity/name/default relationship support without redundant duplicate indexes. Category partial indexes distinguish roots from children and allow the same child name under different parents. Merchant (normalized_name) supports matching. Rule (active, priority) supports ordered active-rule selection; (normalized_pattern) supports pattern lookup. Sender unique identity supports authorization lookup. Do not add speculative archive, text-search or FK indexes without frozen support.
