# M06-P04 — Duplicate webhook and reply-failure resilience

**Milestone:** M06 — WhatsApp Integration
**Status:** ACTIVE / NOT AUTHORIZED FOR IMPLEMENTATION.
**Authority:** [Accepted Activation Review](M06-ACTIVATION-REVIEW.md) §6 and §8; [M06 overview](M06-OVERVIEW.md).

- **Objective / owner:** Prove that webhook replay, ambiguous Finance responses and reply failures cannot duplicate a financial effect. Owner: n8n resilience and cross-boundary tests; accepted M05 Inbox remains the source of financial idempotency.
- **Exact permitted paths:** `docs/tasks/active/M06-P04.md`; `integrations/n8n/m06/**` (retry/recovery logic and tests); `apps/api/src/inbox.test.ts`; `packages/core/src/application/inbox/claim-inbox-message.test.ts`; `tests/integration/inbox/inbox-message.test.ts`; `tests/integration/inbox/api.test.ts`. No production Finance source changes.
- **Dependencies:** P01–P03 accepted, approved reply policy, explicit P04 authorization; existing real PostgreSQL test environment. Gate 0 is needed only for separately approved live failure injection.
- **Required outputs:** Deterministic duplicate/response-loss/reply-failure fixtures, bounded recovery rules, delivery-state evidence and real PostgreSQL regression results. Document that financial effects are exactly once by Inbox identity while outbound reply is best effort and may be repeated or lost after ambiguity.
- **Acceptance criteria:** Duplicate processed webhook yields one logical financial effect; same-identity replay after ambiguous Finance timeout cannot create a second effect; concurrent replay preserves Inbox uniqueness; reply failure leaves committed finance state intact; reply-only retry does not call Finance or create another Transaction; invalid-origin replay is rejected before either path.
- **Tests:** Unit tests for retry state and identity preservation. Real PostgreSQL integration tests with independent connections cover duplicate/concurrent claims, stable Inbox identity and transaction count. Simulated E2E injects lost Finance response, duplicate webhook, send failure and ambiguous outbound timeout, asserting exact Finance call/effect and reply-attempt counts; no assertion of exactly-once outbound delivery.
- **Security / financial invariants:** Verified ingress is required for every replay; unauthorized/group/`from_me` events remain no-effect; no raw unauthorized Inbox persistence; canonical PostgreSQL idempotency and existing financial constraints remain authoritative.
- **Forbidden scope:** Reimplementing idempotency in n8n as financial source of truth, re-running Finance for reply retry, new financial operations, production schema changes, live fault injection without permission.
- **Gate / human authorization / stop:** Local tests need no Gate 0; live resilience tests require Gate 0 PASS, reviewed isolation plan and separate VPS/Lab authorization. Stop if a duplicate effect appears or required real PostgreSQL evidence is unavailable; do not claim acceptance from mocks alone.
