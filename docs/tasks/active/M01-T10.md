## Objective

Create and validate the application packaging required for later Lab deployment while remaining fully local. This task is packaging only, not VPS deployment. It creates a production-oriented API Dockerfile/build with multi-stage image where appropriate, Node 24-compatible runtime, deterministic pnpm install/build, correct monorepo/workspace handling, non-root runtime user where practical, proper .dockerignore, environment configuration via runtime variables, health/readiness endpoints available inside the packaged API, local container startup validation, and clean shutdown behavior. Gate 0 has not automatically been satisfied merely because local Docker works.

## Implementation Sequence

1. **Inspect current build output and runtime entrypoint**:
 - Run `pnpm build` to verify build produces expected output
 - Identify which files are needed at runtime vs build-time
 - Check `apps/api/dist/` structure
 - Verify whether the API currently has an actual production HTTP startup entrypoint/listener or only an app builder/export used by tests
 - If no production listener exists, create the smallest runtime bootstrap required under `apps/api/**` (this does not authorize business/domain changes)
 - The packaged API must actually start as a process, listen on a runtime-configurable port, bind to 0.0.0.0 inside the container, and handle startup errors safely

2. **Create production Dockerfile**:
 ```
 apps/api/Dockerfile
 ```
 - Use multi-stage build:
   - Stage 1: Build stage with full devDependencies
   - Stage 2: Runtime stage with only production dependencies
 - Base image: Prefer a pinned Node 24 Debian/bookworm-slim-compatible runtime/build image (e.g., `node:24-bookworm-slim`)
 - Do NOT default to Alpine merely for image size; avoid introducing musl-specific differences without a demonstrated reason
 - Exact compatible Node 24 image/tag may be selected during implementation and must be recorded in the completion report
 - Copy only necessary files to runtime stage
 - Install production dependencies only in runtime stage

3. **Configure monorepo workspace in Docker**:
 - Ensure pnpm workspace is respected in build
 - Copy workspace files appropriately
 - Build all packages that API depends on

4. **Add non-root runtime user**:
 - Create dedicated user for running the application
 - Set appropriate file permissions
 - Run application as non-root user

5. **Create `.dockerignore`**:
 - Exclude `node_modules/` (will be installed in build)
 - Exclude `dist/` (will be built in build)
 - Exclude `.git/`
 - Exclude test files
 - Exclude documentation
 - Exclude `.env` files
 - Exclude IDE configurations

6. **Configure environment variables**:
 - Use ENV instructions for non-sensitive defaults
 - Document required runtime environment variables
 - Never hardcode secrets or credentials

7. **Implement health/readiness in container**:
 - Ensure `/health` and `/ready` endpoints are accessible
 - Configure Docker HEALTHCHECK instruction to use `/health` as the container liveness/process-health signal
 - Do NOT use `/ready` as the Docker liveness healthcheck
 - `/ready` must be validated separately during smoke testing with PostgreSQL available
 - This preserves the M01-T06 distinction: `/health` = process alive; `/ready` = critical PostgreSQL dependency ready

8. **Implement clean shutdown**:
 - Handle SIGTERM signal properly
 - Allow graceful shutdown of HTTP server
 - Close database connections cleanly

9. **Create local validation**:
 - Build Docker image locally
 - Start container with isolated PostgreSQL
 - Verify `/health` endpoint responds (container liveness)
 - Verify `/ready` endpoint responds when PostgreSQL is available (readiness)
 - Test clean shutdown behavior (SIGTERM)
 - Verify API binds correctly and is reachable from host
 - Verify runtime user is non-root
 - Verify no secrets are exposed in container
 - Verify no VPS/shared infrastructure is touched

10. **Document Docker usage**:
 - Add README section explaining how to build and run locally
 - Document required environment variables
 - Document how to connect to local PostgreSQL
