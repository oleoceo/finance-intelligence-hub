## Acceptance

- Authentication occurs before body validation. `finance:ingest` can call only Inbox; `finance:admin` direct financial routes remain protected. Match frozen request/response/error shape, including `403 SENDER_NOT_AUTHORIZED`, duplicate message and confirmation response. Return structured reply result with no raw sensitive content leaked.
- Order: service auth → technical/group/from_me filter → normalize sender → authorize active sender → raw Inbox insert/claim → interpretation → confirmation or financial execution → reply. Recheck authorization in transaction before effect. Duplicate processed message does not execute or send again; failed/stale retry reuses same row and fences old claimant.
- One outer PostgreSQL transaction commits final Inbox/Interpretation/Confirmation state with Transaction, idempotency and Audit, or rolls them back together. Confirmation resolution and original Inbox finalization are in the same commit as the confirmed effect. If effect fails, retry remains safe and no terminal Inbox claims a nonexistent Transaction.
- M04 financial validation, Money/date/currency rules, lock order, idempotency fingerprint and error translation still apply. `finance:ingest` cannot bypass admin via direct route. No external transport or AI prerequisite.

**Required tests:** API unit for auth-before-validation, scope separation, filtering and response mapping; real API/PostgreSQL integration for unauthorized zero raw rows, filtered zero financial persistence, duplicate processed, failed retry, stale reclaim, concurrent duplicates/revocation, full Expense/Income/Transfer roundtrip, rollback on Audit/idempotency/Inbox failure, confirmation execution/supersede/expiry. Use independent connections and deterministic synchronization for races; assert exact rows and effects. Preserve M04 E2E and suites.
